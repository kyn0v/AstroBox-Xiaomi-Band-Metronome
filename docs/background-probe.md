# 后台运行试验：0.6.0-beta.1

此包用于 [issue #1](https://github.com/kyn0v/astrobox-xiaomi-band-metronome/issues/1) 的小米手环 9 Pro 实机验证。**它不代表已经实现或验证了后台打拍。** 不要求 Root、刷固件、额外定位/音频权限或修改系统。

## 进入试验

1. 在首页设定 **120 BPM、4/4**，打开振动；建议在节拍编排里先把四拍都设为短振动，以便听/感知是否漏拍。保留正常模式的完整验证，不要一开始边跑步边试。
2. 首页下滑到配色，点击「**后台试验（测试版）**」。这个入口会清除历史页面栈，以便测试系统级返回行为；使用「停止并回首页」恢复普通界面。
3. 点击「**开始 5 分钟**」。未点击时不会振动，上次运行也不会自动恢复。

## 建议分开进行的测试

每种场景重新开始一轮，记录设备型号、固件版本和应用版本。每轮不要超过五分钟。

### A. 前台基准

- 保持试验页面显示 30–60 秒，与另一只节拍器或秒表作参考。
- 检查是否连续、是否出现明显漏拍；页面应显示后台回调为 0。
- 点击「停止」，确认不再产生新振动。已经开始的单次振动可能完成后才停止。

### B. 尝试返回表盘

- 重新开始，点击「**尝试返回表盘**」，或使用系统返回手势。
- 记录是否确实回到表盘、振动是否立即停止、10 秒和 60 秒后是否还保持节拍。
- 如系统允许切换其他应用，可以再单独测试；不要以仍在本应用内切页代替系统后台测试。
- 手动重新打开应用。如回到普通首页，程序会先停止仍保留的实验会话，避免两套节拍叠加。进入试验页查看记录。
- 系统可能直接销毁应用而不是保留后台，这本身就是需要确认的结果，不应通过持续下载、虚假音频或定位来掩盖。

### C. 系统熄屏

- 单独一轮，在保持试验页面时用设备提供的系统操作尝试熄屏。
- 观察屏幕是否真正关闭、是否回表盘，以及振动表现。
- 「前台暗屏」并不是这个测试。设备是否允许在请求保持亮屏时强制熄屏，取决于固件。

### D. 前台暗屏替代方案

- 开始后点「**前台暗屏**」，显示黑底并停止页面内容展示，但仍然是前台、仍请求保持屏幕开启。
- 点击黑色页面恢复控制；右滑也先退出暗屏，不会误判为已进入后台。
- 五分钟结束或定时异常停止时恢复控制页。
- 不把黑屏当作系统熄屏，不预先承诺省电效果。

## 记录如何解读

- **应用隐藏事件**：框架是否调用过应用级 `onHide`。点击“尝试返回”本身不会增加这个数。
- **后台 / 总回调**：应用不可见时收到的 JS 定时回调次数和总次数。它不是硬件马达确认信息，不能仅凭数字就认定用户实际感受到了准确节拍。
- **最长间隔**：两个回调之间或恢复执行时观察到的最大墙钟间隔。大幅跳变会停止试验，不会补发一串振动。
- **定时中断，已停止**：间隔超过 `max(1.5 秒, 三个拍位间隔)`。这说明这轮不能提供稳定节拍，但单次结果不能证明所有固件都如此。
- **上次中断，后台情况未知**：只读到了未完成的运行标记，可能被关闭、回收或未完成保存，不能当成后台成功或失败的确证。
- **应用关闭，试验已停止**：收到了应用销毁回调；后台不能继续由这份 JS 实例调度。
- **试验记录存储不可用**：不要依赖跨重启的记录，直接报告观察结果。

记录只在开始、应用显隐和停止等边界保存，不会每拍写存储。系统回收进程时最后一次异步写入可能来不及完成。

## 停止与安全边界

- 「停止」或「停止并回首页」停止定时并释放保持亮屏请求。
- 五分钟上限按墙钟计算。JS 若被挂起，不能主动执行停止逻辑，但挂起时也无法调度新的逐拍振动；恢复执行时先检查期限，不补拍。
- 检测到较长间隔、时间回退或同步振动异常时停止。
- 正常首页也会结束遗留试验，任何新启动都需要用户操作。
- 不保存“自动继续播放”的设置；重启应用后不会恢复。
- 若出现不适、异常发热或明显耗电，请立即停止，不要继续跑步测试。
