# 设备能力检测（历史记录：0.6.0-beta.2）

**beta.3 已移除此入口及设备信息声明。** 已收到用户确认：只有 `vibrator.vibrate` 报告支持，重复任务接口不支持。固件/运行时完整信息仍未提供。以下为旧版检测说明；当前版本用法见 [前台暗屏说明](foreground-dark.md)。

这次测试只收集判断后台方案所需的基础信息，**不再试图靠 JS 定时器维持后台振动**。包名、项目签名沿用现有应用，版本号为 `0.6.0-beta.2`，versionCode 为 `21`。

## 如何进入

1. 手动安装收到的 RPK。不要为了安装而自动卸载旧应用或清空设置；若覆盖安装报错，先记录错误。
2. 打开节拍器，首页**下滑进入配色**。
3. 点击「**设备能力检测（只读）**」，不要点下方的「后台试验」。
4. 页面会自动读取一次设备信息；最多等待约三秒，失败/超时也会显示结果。
5. 用「上一页／下一页」查看五页，建议各拍一张照片或截图。长值可点击打开详情，再点击关闭回到原页。
6. 「重新检测」可手动重试；「返回」或右滑离开。返回/隐藏会取消尚未结束的查询，晚到回调不会再改旧页面。

## 五页内容

| 页码 | 内容 | 重点 |
| --- | --- | --- |
| 1/5 | 型号、设备代号、系统版本、API Level | 以设备实际返回为准，不用应用最低 API 要求代替 |
| 2/5 | 运行时版本/版本号、系统版本号、应用版本/版本号 | 核对固件与运行时；确认是 beta.2 / 21 |
| 3/5 | `vibrator.vibrate`、`vibrator.start`、`vibrator.stop` | 只查询，不调用这些振动方法 |
| 4/5 | audio、geolocation、request、event | 只查询名称，不播放音频、定位、下载或订阅事件 |
| 5/5 | timer、alarm、notification 候选名称 | 这些不是已确认的 Vela API，仅作字符串能力查询 |

若整个界面显示「系统未提供能力查询接口」，仍请反馈前两页设备信息；这不是坏结果，也不能解释成所有接口都不支持。

## 状态怎么理解

- **报告支持**：`app.canIUse` 返回了 `true`。不代表已经获得权限、不代表调用能成功，更不代表后台能保持运行。
- **报告不支持**：该次能力查询返回了 `false`。仍需结合固件版本和官方支持表判断。
- **无法查询**：当前系统对象没有提供可调用的 `app.canIUse`，不能据此认定被查询接口不存在。官方文档将查询方法标为 API Level 3+。
- **查询异常**：读取或调用能力查询方法出现异常。不会显示可能夹带隐私的原始错误文字。
- **结果未知**：查询没有返回标准布尔值。
- **未返回**：设备没有返回这个信息字段，例如旧系统可能没有 API Level 字段。
- **设备信息读取失败 / 超时**：不能把缺失字段当成零或 API Level 1。若有数字错误码，会显示在状态栏，例如 `(203)`。

字段中的控制字符会被替换，超长文本会用 `...` 明确标记截断。结果只在当前页面实例内存中保留；退出应用后可能丢失，因此请在这次查看时记录所需页面。

## 隐私和安全边界

检测只使用：

- `app.getInfo()`：仅保留包名、版本名和版本号；
- `app.canIUse(name)`：若查询方法存在，查询接口名称；
- `device.getInfo()`：仅保留型号、设备代号、系统/运行时版本和版本号、API Level。

不会读取唯一设备 ID、序列号、账号、MAC 地址、位置或网络凭据；不写入检测报告，不上传结果，不发通知，不加载动态库，也不会启动振动/音频/GPS/下载/后台服务。若有上一轮尚未结束的振动试验，进入检测页会先停止它。

原有节拍器仍然可以由用户正常启动；**只读承诺针对本检测入口，不是说整个应用失去了振动功能**。系统状态栏或通知里的个人信息仍应在分享截图前遮盖。

## 反馈格式

最简单的方式是发回五页照片，并说明：

```text
安装是否成功：
1/5 型号、设备代号、系统版本、API Level：
2/5 运行时版本/版本号、系统版本号、应用版本/版本号：
3/5 vibrate / start / stop：
4/5 audio / geolocation / request / event：
5/5 timer / alarm / notification：
顶部状态或数字错误码：
翻页、查看详情、返回是否正常：
```

这份检测本身不能让原先不支持的后台功能生效。它用于减少未知条件，决定是否还有必要做一个有限次数、可取消的原生任务验证，或应直接向平台维护者确认开放能力。
